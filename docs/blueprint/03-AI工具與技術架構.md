# 03 AI 工具與技術架構

> 規劃文件；整理於 2026-11-11，同日修訂（新增進出場助手的 AI 層）。模型與價格取自 Claude API 的官方資料（快取日期 2026-10-06），實際建置前要再確認。

## 1. 原則：AI 做什麼、不做什麼

| AI 負責 | AI 不負責 |
|---|---|
| 收集與整理資訊：新聞、法說會、公告、數據 | 計算任何分數、價位、部位：一律由固定規則計算 |
| 解讀局勢分數，寫成文字說明 | 決定局勢狀態：由 [02 §1.1](02-平台功能規劃.md) 的規則決定 |
| 起草情境、提出反方論點 | 決定情境機率與行動：由自己決定 |
| 提醒、教練、起草檢討報告 | 下單、修改投資政策或劇本 |

其他原則：
- **可檢驗**：AI 寫的每個情境機率都記錄下來，和人的判斷一起用布瑞爾分數評估（[01 B3](01-知識與方法論.md)）。AI 不比基本率準，就降低它的權重。
- **可追溯**：AI 的每個說法都附上資料來源；沒有來源的內容標示為推論。
- **失敗時降級**：AI 無法使用時，所有功能照常以規則運作，只少了文字說明。
- **隱私**：持股、金額等個人資料只在必要時送出，可以先換成比例或代號。
- **成本上限**：每個 agent 設每月預算，超過就停用並提醒。

## 2. 產品內的 agent

| agent | 觸發 | 讀取（工具） | 輸出寫到 | 建議模型 |
|---|---|---|---|---|
| 進出場助手 | 打開計畫單、每日掃描、使用者追問時 | 規則算出的計畫單與檢核結果、研究卡、策略卡、局勢參數、持倉 | 計畫單上的白話說明、矛盾提示、反方情境、追問的回答 | Claude Sonnet 5.5；複雜追問升級 Claude Opus 5.5 |
| 局勢解讀 | 每週一次，加上局勢狀態改變時 | 局勢分數與歷史、總經數據、新聞搜尋 | 局勢說明、情境工作台的情境草稿 | Claude Sonnet 5.5 |
| 紅隊（反方） | 寫完情境或研究卡結論時，由人按下 | 情境、研究卡、壓力測試結果 | 反方論點與「會讓你錯的條件」 | Claude Opus 5.5 |
| 事件監控 | 每個交易日 | 事件日曆、公告、法說會、持股與研究卡的失效條件 | 今日頁提醒；觸發研究卡複查 | Claude Haiku 5.5 |
| 風險審查 | 交易前檢核時 | 持股、風險儀表板、壓力測試 | 檢核頁的文字說明：這筆交易讓風險怎麼變 | Claude Sonnet 5.5 |
| 交易教練 | 每週一次 | 交易日誌、計畫單與執行品質、情緒紀錄、局勢狀態 | 每週回饋：重複犯的錯、局勢與行為的關聯、滑價與違反出場規則的型態 | Claude Sonnet 5.5 |
| 檢討員 | 每月與每年 | 局勢判斷回顧、決策日誌、歸因 | 月報與年度檢討報告草稿、政策修訂建議 | Claude Opus 5.5 |
| 研究助理 | 財報季與法說會後 | 財報、法說會簡報與逐字稿、重大訊息 | 研究卡的論點更新與失效條件檢查 | Claude Opus 5.5 |

**進出場助手的 AI 層**（[02 §3](02-平台功能規劃.md)）：
- 輸入是規則已經算好的計畫單與三級檢核結果；AI 不重新計算價位、股數或停損。
- 工作是：用白話說明每條建議的依據；找出矛盾，例如研究卡說等待、策略卡卻出現進場訊號；提出反方情境；回答「為什麼只買第 1 批？」這類追問。
- 每句話都要引用規則或數據；給出規則以外的買賣指示（例如「我建議全部買進」）在 eval 中判定失敗。
- 沒有金鑰或超過預算時，計畫單照常顯示，只少了說明。

**怎麼做**：
- **單次任務**：紅隊、風險審查是一問一答，用 Claude API 的 Messages API 加上結構化輸出（`output_config.format`）就夠了。
- **多步驟任務**：局勢解讀、研究助理需要搜尋與讀取多個來源，用 API 的工具呼叫（Tool Runner），或 Managed Agents。
- **排程**：事件監控、每週局勢、教練、月報，用 Managed Agents 的排程部署（scheduled deployments），不必自己架排程器。
- **不急的工作**：月報、年度檢討、教練可以用 Batch API，成本減半。

## 5. 技術架構演進

### 階段一：現在
- 純前端（React），資料存在瀏覽器的 localStorage。
- GitHub Actions 每天抓資料、交叉驗證，產生靜態 JSON。
- 優點：免費、隱私好、沒有伺服器要維護。
- 限制：不能跨裝置同步、不能推播、不能在背景執行 agent、不能安全保存 API 金鑰。

### 階段二：加上輕量後端（選擇性）
- 候選：Cloudflare Workers 加 D1 資料庫，或 Supabase。費用與免費額度待查證。
- 用途：
  - 加密同步：資料在瀏覽器加密後才上傳。
  - 推播：局勢改變、劇本觸發、到價、熔斷。
  - 保存 API 金鑰，讓 agent 在背景執行。
- 保留匯出與匯入，隨時可以回到純本機模式。

### 階段三：agent 執行
- 排程 agent 用 Managed Agents：設定檔放在版本控制中，用 `ant apply` 同步；每個 agent 有自己的工具權限、預算與 eval。
- 需要自己控制流程的部分，用 Claude API 加工具呼叫，由後端執行。

### 品質與安全
- **eval**：每個 agent 建立固定的測試集，例如過去的局勢與事件，檢查輸出是否引用來源、是否越權（例如給出買賣建議）、格式是否正確。
- **權限**：agent 只有唯讀工具；任何寫入都要人確認。
- **紀錄**：每次 agent 執行的輸入、輸出與成本都記錄，方便檢討。

## 7. 階段 6 的決定（2026-11-12）

- **不用付費 API 金鑰**：依使用者的決定，六個產品內 agent（事件監控、進出場助手的 AI 層、局勢解讀、紅隊、交易教練、檢討員）都做成**提示詞範本**。網站把規則算出的結果整理成提示詞，使用者複製到自己的 Claude 對話。
  - 範本在 `src/lib/ai/prompts/`，固定開頭要求 AI 只說明、不給新建議、不改規則、資料不足說不知道。
  - 金額預設隱藏，只留百分比、價格與 R 倍數。
  - 每個範本都有固定題目的自動評估，以及人工評分表：見 `docs/ai-eval.md`。
- **後端**：Cloudflare Workers 免費方案加 KV。同步資料在瀏覽器以密語加密（PBKDF2 31 萬次、AES-256-GCM）；推播不帶內容，通知由裝置自己計算。部署步驟見 `docs/backend-setup.md`。
- **原本需金鑰的 AI 總經、AI 研究**：保留，填了自己的金鑰才啟用；後端不保存任何金鑰。
- **代價**：AI 不會自動執行，要手動貼上；換來的是零 API 費用，且 AI 無法自動修改任何資料。
